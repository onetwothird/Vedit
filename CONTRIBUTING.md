# Contributing to Vedit

Thanks for helping creators edit less and publish more.

## Dev setup

Engine (Python):

```bash
git clone https://github.com/onetwothird/vedit && cd vedit
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[all,dev]"
vedit doctor
pytest -q
```

Tests use a synthetic video and a fake transcript, so they don't need Whisper models or network access.

Vedit Studio (the desktop app, in `app/`), with Node 20+ and Rust:

```bash
cd app
npm ci
npx tsc --noEmit && npx vitest run      # types and unit tests
npx playwright test                     # screens, against the demo engine
VEDIT_DEV_ENGINE=1 npm run tauri dev    # the real app on real videos, engine from ../scripts
```

`npm run dev:mock` is a browser demo with a sample clip; it never touches real files. To try a change on a real
video, use `tauri dev` as above.

## Architecture (5-minute tour)

```
analyze.py / transcribe.py   footage -> facts (word timings, silences, scenes, contact sheets)
autocut.py / presets.py      facts -> draft edl.json (the edit, as data) + brand kit
edl.py                       edl.json -> resolved timeline (words -> times, multicam offsets, mapping)
render.py                    timeline -> per-clip cached segments -> final pass (overlays, captions, audio)
captions.py                  timeline words -> ASS/SRT
story.py / tts.py            script + photos -> voices + edl.json
auto.py / vedit.py           one-command pipeline / CLI entry point
studio_server.py             local API for the app: projects, jobs, clip edits, media for the preview
edl_ops.py                   the edits the app sends (cut, restore, trim, fix a word, patch a section)
app/                         React screens (Import, Pick, Edit, Export) in a Tauri shell
SKILL.md                     how Claude Code drives all of the above
```

Key idea: **every edit is JSON**. Features should be new edl.json fields that render.py understands. The AI, the app
or a person only writes data, and the renderer stays deterministic.

## Guidelines

- Standard library + ffmpeg first. Heavy dependencies must be optional, with a graceful fallback.
- Every new edl field goes into `references/edl.md`, and every new command into `SKILL.md` + README.
- Paths inside ffmpeg filters go through `common.filter_path()` (Windows drive letters).
- Add a test in `tests/` (engine) or next to the component (app) for new behavior.
- **The preview must match the export.** When you change how something is drawn (captions, text, b-roll, colour,
  speed), change the preview and render.py together, and extend `tests/test_edit_tools_render.py`, which renders a
  real clip and reads the frames back.
- Never log, print or save an API key or the engine token. Keys live in the OS credential store; the token only in
  memory and the environment.
- Don't commit footage you don't own. Test media is generated by the tests.

## Pull requests

Fill in the template: what changed and why, and how you tested it (`ruff`, `pytest`, the app tests, and a real
render checked with `vedit frames`).

## Good first issues

- More caption styles (karaoke fill, emoji emphasis)
- Crossfade transitions between clips
- Auto b-roll suggestions from the transcript
- Speaker diarization for single-mic podcasts
